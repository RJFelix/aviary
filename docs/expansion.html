Before the ideas

Four things the brief asserted that turned out to be false

I wrote the shared brief from my own reading of the harness. Four separate agents came back having checked it, and the corrections change what is worth building. All four are verified in source or in the real session store, not taken on an agent’s word.

rlm() does not return the child’s answer Verified

The brief called a sub-agent “an awaited function call, not a fire-and-forget task.” The opposite is true. await rlm('sub-task') returns immediately at task admission with rlm_child_id, name, session_dir, model — and, in the harness’s own words, “never waits for or returns the child’s answer.” Replies arrive out-of-band via agent_message.send(..., receiver_role='parent'), on some later turn, or never.

So a sub-agent is fork() plus an unreliable mailbox. The consequence is structural and it is the single best idea in the whole fan-out: the return edge is stored nowhere on disk. Flock draws spawn edges because spawn edges are the only edges that exist.

harness/packages/coding-agent/src/core/prompts/rlm.ts:150

There are 22 hook events, not 5 — and two of them are levers Verified

The brief listed five. ExtensionEvent is a union of 22, with 27 on() overloads. The two I had missed are the two that matter most:

ContextEvent returns ContextEventResult { messages } — an extension can rewrite the message history the model sees, per LLM call, without touching disk. ToolCallEvent returns { block, reason }, and the type’s own comment reads: “To modify arguments, mutate event.input in place instead.” Because ipython is the only tool, that one handler is a complete permission system that can edit the Python before it runs.

core/extensions/types.ts:845, :874, :976, :995

The harness already has a bidirectional UI protocol. Aviary drops it on the floor. Verified

I described hooks as one-way and speculated about “bidirectional hooks that ask the human a question.” They exist. In RPC mode the harness emits extension_ui_request with methods select, confirm, input, editor, notify, setStatus, setWidget, setTitle, set_editor_text, and waits for an extension_ui_response correlated by id. The host is expected to render extension UI.

RPCClient.swift handles none of them. Today an extension that asks a question gets silence until the timeout fires. There is even a set_editor_text method that would let an extension prefill Aviary’s composer.

modes/rpc/rpc-types.ts:302–305 · modes/rpc/rpc-extension-ui-context.ts:50, :152

Zero of 80 sessions have ever forked — which kills a proposal Verified

Facet 05 proposed a “Branch Gutter” rendering every leaf in the entry tree, then asked for the cheap falsification test first: count the leaves before writing any Swift. I ran it over the real store. Every one of the 80 sessions has exactly two graph leaves — and in 66 of them the signature is ('message','session'): the session header entry’s id is simply never anyone’s parentId. That is a detached header, not a branch.

One real conversational leaf per session, 80 for 80. The Branch Gutter would be an empty rail. The same parser work should ship as Compaction X-ray instead, where the hidden-to-visible ratio is nonzero on every long session — exactly the fallback that agent named before it knew the answer.

Independent agreement

Five agents, working blind to each other, reached for the same lever

None of the ten could see another’s output. They were given different facets and different method tuples on purpose. So agreement is evidence, not echo — and they agreed twice.

Agreement one: the payload-replacing hook is the only real control point

Five of ten independently built their strongest proposal on before_provider_request’s licence to replace the outgoing payload — each arriving from a different direction, and one of them noting the hook is documented as being “mainly useful for debugging provider serialization.” Its used purpose has drifted a long way from its stated one.

Agreement two: the target is the skills catalogue

Three of the ten “sharpest” picks aim at the same number from three unrelated facets, and a fourth aims at its sibling defect. The number is the one measurement that started this whole line of work: 68 installed skills = 46,713 characters ≈ 10,883 tokens = 62.7% of the input on a trivial two-message run, whether or not any skill is used.

Facet 03 called it Warrant (admission by relevance, via resources_discover). Facet 07 called it Bonded Knowledge (a staging tier the agent can fetch from but does not carry). Facet 08 called it The Gate (rewrite the block on the wire). Facet 01 aimed at the adjacent wound: the continual harness’s 6-entry, 180-character, alphabetical injection cap.

Two of them independently landed on the same reason it is safe here and nowhere else: because ipython is the only tool, withholding a skill’s advertisement withholds discovery, never capability. The module stays importable and the SKILL.md stays readable by path. A denial costs latency, not a lobotomy. In a Read/Write/Bash harness the same move would be silent capability loss.

And both then raised the same objection: a pruned skill does not error. It makes the agent look stupid in a way indistinguishable from the model being bad.

Facet 01

The continual harness, seen

negation×abstraction-lift→list·hierarchicalness, reversibility, predictability

Strip the vocabulary off /refine and what is left is a write-back cache with no eviction policy and an alphabetical read policy — where the cache is the thing’s personality. Neighbouring domains solved it and Prime Agent kept none of the answers: genetics separates germline from soma and makes meiosis the promotion gate; publishing has the editorial diff and the erratum; accounting has double entry, journal for provenance and ledger for state. The superrepo next door already runs the accounting answer.

Two of the negations turn out to half-exist in code and have no reader. Journaled: refinements.jsonl and the prime-agent.refinement custom entries already store full before/after snapshots per edit — a real diff log, written and never read. Tiered: HarnessEntry.metadata is a free-form dict and path is the primary sort key, so tiers and expiry are expressible inside the existing format, as demotion rather than deletion.

Facet 04

One stateful tool instead of many stateless ones

dimension-identification×tree-finding→timeline·decomposability, symmetry, side-effect

The tree-walk inverts the product. Going up from the kernel namespace → session state → agent context → what the model believes, each level up is more inspectable than the level below it. And going across: the transcript JSONL, harness_state.json, rlm-subagents.jsonl, worker descriptors and the wire log are all durable, diffable, and already read by Aviary. The live image is the one sibling with no reader.

Slide down one level and Aviary is not an agent GUI at all: it is a debugger attached to a long-running Python process that happens to be driven by a model.

The asymmetries found on the timeline are the specifics worth having. On restore, the model is told what came back via a system notice; the human is told nothing. Only three vendor MIME types are read from display_data, so image/png and text/html fall on the floor. Compaction shrinks the narration and not the image, and divergence begins there. Nothing in modes/rpc/ mentions the kernel at all, so the message tree forks and the image cannot. And the measured afterlife: 105 artifact directories, 58 MB of dill, median 16 saved names, max 185, zero garbage collection.

Facet 05

Git’s data model, none of git’s verbs

abstraction-lift×tree-finding→timeline·scope, homogeneity, polarity

Lifted: a monotonic append log, interpreted as a pointer machine whose pointer is implicit in file position. The privileged leaf is declared nowhere — it is inferred from whoever wrote last. That is git without a HEAD file: the DAG, the immutable objects, the cheap branching, the non-destructive history, and no branch -a, no reflog, no diff, no log --graph.

The sibling table settles the question I was chewing on earlier in this conversation. A Prime Agent session is the only row that owns a live kernel and a mutable prompt and a cron table. Its nearest sibling by state-weight is a Jupyter kernel; its nearest by scope is a git worktree. Both are week-scale, not task-scale.

Narrow a session to one task and the harness’s own numbers stop making sense: auto-refine needs 25 assistant turns plus a 20-minute cooldown and only fires on root sessions, so a task-sized session never refines once. Widen it to a week and the numbers land. One session = one worktree-scale unit of work, and branches are its tasks. The harness already built for that; only the UI assumes otherwise.

Facet 06

Standing a watch

dimension-identification×abstraction-lift→notation·modularity, decomposability, scope

This facet invented a notation for unattended agent time — one lane per root session tree, time flowing right, the harness build as part of the lane’s identity because two builds cannot share a daemon.

  =  running, fully attended (events + input)     attach
  ~  running, watched but mute                    slim_attach
  -  running, nobody watching                     worker outlives client
  o  self-woken tick                              cron job / heartbeat
  ?  blocked on a question to an absent principal start_side_question
  !  we asked, we don't know if it ran            command_result_uncertain
  x  worker gone, lease file survives             session-leases/<sha256>.lock
  >  custody transfer, resume from cursor         reattach + event_sequence
  #  generation bump, replay lost                 event_replay_not_available
  /  answers doctor, refuses commands             wedged supervisor

  a real evening:
    sess-4f1@2.1#7 : ==== ---- o --- ?????????? > ==
    sub-a9         :      -------- ! x
    sess-0bd@2.0#1 : ==  /  ......

The value is in the slots the notation refuses to leave blank. Every - span must name who gets told when it ends — the protocol has no notify sink, the span just stops. Every ? must carry an age and an escalation; start_side_question has neither. Every > must declare its resume basis, and the third case — replay lost — is a designed experience nobody designed. Every x needs a reaper claim: leases are sha256(realpath) directories whose owner record nothing owns the burial of.

Lifted, the daemon is a persistent laborer continuing under an intermittently absent principal, where the right to speak to it is a transferable token and obligations raised during absence accumulate unclaimed. That is a watch, and every domain that stands watches invented the same three artifacts Prime Agent lacks: a log book written for the relief, an escalation ladder with a timer, and a chain-of-custody receipt. Aviary’s opportunity is not “GUI for a daemon.” It is to be those three modules the monolith never grew.

Facet 07

Hooks are not the API

cross-domain-reinstantiation×dimension-identification→cycle·intentionality, decomposability, purpose

Drawn as a cycle, the hook surface reveals closure constraints nobody documents. resources_discover is the only phase that can change what exists, and it fires before any prompt is known. context is the only phase that can change what is remembered without touching disk. before_provider_request is the only phase that sees ground truth. after_provider_response is the only phase deliberately blinded — status and headers, no body. And the arc back to resources_discover runs only through /reload: the cycle has exactly one re-entry point, and Aviary controls it.

The diagnostic absence: there is no hook between after_provider_response and message_start. Nothing can gate a response before the user sees it. So Aviary’s amendment window has to be its own render layer, not a harness hook.

Two readings this forces. First, the most valuable hooks are the ones whose used purpose has drifted from their documented one — before_provider_request is documented as “mainly useful for debugging provider serialization,” and Aviary’s entire context-breakdown screen is a repurposing of it. Second, and this is the thesis: almost no interesting policy is one-hook-decomposable. A spend cap needs both provider hooks plus persistent state. An approval gate needs tool_call plus a host that can ask a human. Hooks are not the API. Compositions over hooks, plus a host that answers questions, is the API.

Re-instantiated as a customs regime — goods moving past checkpoints with statutory powers — four imports fall out. Pre-clearance: approved shippers skip inspection, so a nag-free approval gate needs a trust registry, not better rules. Bonded warehouse: goods sit in-country, un-cleared, not yet dutiable — the missing tier for knowledge. Single window: one filing satisfies every agency, whereas today each extension invents its own env var and log file. Amendment window: declarations may be corrected within a period — the one Prime Agent does not offer.

    Verified The protocol exists and Aviary handles none of it. Bidirectional hooks are not a feature to invent. Hardest part: timeout and cancellation semantics while a run streams, with several dialogs outstanding, correlated only by id.

    M
  • Bonded Knowledge▮ top pick

    resources_discover emits a per-session staging directory: superrepo knowledge/ notes rendered as skills, ranked against the prompt, and the 68 installed skills pruned to the ones that earn their tokens.

    Path-level, so legal without forking — and it is the same relevance-ranked injection the superrepo’s whisper hook already proves in production.

    M/L
  • Tariff

    A running cost ledger that can downgrade a request instead of failing it.

    Lives in the same extension Aviary already ships, so it costs one more pi.on. No response body means accounting is always one call stale, and RLM children are separate processes with separate budgets.

    S/M
  • Single Window

    Aviary becomes the extension host: authoring, install, per-run composition, and one shared event bus every extension files into.

    Handlers chain in extension load order, and two of them may replace their subject. Order is semantics — and nothing in the harness shows or controls it. Hardest part: showing that ext A’s prompt rewrite was clobbered by ext B.

    L
  • Divergence Ledger

    A tracked file plus a Health check listing every fork patch with the reason it could not be an extension — and re-testing that reason.

    Its only current entry is the reasoning-token patch, whose negative proof is structural: after_provider_response fires before the stream body is consumed, so output_tokens_details is unreachable from any extension. “Extension-only unless proven impossible” is a real discipline only if the proofs are written down and re-run when upstream moves.

    S

Its own strongest objectionA timing objection dressed as an architectural one: resources_discover fires at startup and on /reload, before input and before_agent_start — so at the moment you must decide what the agent may carry, you do not yet know what it was asked. Aviary can paper over this because it owns the prompt box, but that makes relevance a property of the host, not the session, and it breaks for any run Aviary did not start. Ship the bonded tier — a listed, fetchable index of what was held back — or it is silent capability loss.

Facet 08

An unpriced commons on a fixed shelf

organon-construction×abstraction-lift→lattice·scope, connectivity, age

Lifted: a fixed-size shelf; a population of candidates; each candidate’s advertisement occupies shelf space permanently, at no cost to the candidate, whether or not it ever sells. Retail answered it with slotting fees. Dynamic linkers stopped statically resolving every symbol and made the symbol table resident and the code paged. DNS ships thirteen root hints, not the zone. Immunology keeps a few memory B cells resident and the naive repertoire out of circulation. Each is a different answer to what earns residency versus what earns retrievability — and Prime Agent answers “everything earns residency,” the one answer none of those domains kept.

Built as a lattice ordered by admitted under strictly weaker conditions, two structural facts appear. There is a diamond: <available_skills> and kernel residency are two non-comparable parents of one child, “a Python skill.” disable-model-invocation: true cuts both edges at once, because the kernel bootstrap is built from the model-visible skill set — so demoting a skill un-imports it as well as un-advertising it. That is the only eviction primitive the harness has, and it is coarser than it looks.

And there is an empty tier, between the 180-character harness entry and the unbudgeted skill advertisement: hook-matched relevant notes. The superrepo has it. Prime Agent has no concept of it. Read along the age axis and the reason nothing works is plain: nothing on the shelf has an age. No ttl, no decay, no last-fired stamp — so an entry /refine wrote once at 02:14 outranks, alphabetically, one that fires daily. Every resident tier is also a flat list of unrelated items; the only densely-connected tiers are the two the harness either cannot persist (the kernel) or does not have (the whisper).

  • Slotting Fees

    A per-skill ledger of chars-injected versus times-fired, with one-click demote.

    The eviction primitive exists here and is honest about its price: demotion also drops the kernel pre-import, so the GUI must show “advertisement withdrawn AND module unimported,” which no generic skill manager models. Hardest part: attributing a firing when the model reads a SKILL.md by absolute path without importing anything.

    M
  • The Gate▮ top pick

    A before_provider_request extension that rewrites <available_skills> down to a ranked budget, with Aviary as its console and auditor.

    One extension file, one documented hook, payload replacement already sanctioned by the type signature. Uniquely safe here: withholding an advertisement withholds discovery, never capability.

    M
  • Knowledge Tier

    Port the superrepo’s whisper hook into the empty lattice tier: dated, git-backed, cross-referenced notes injected only when they match.

    Fills the gap between the two lifetimes Prime Agent actually has. Hardest part: the matcher — keyword overlap is weak and an embedding index is a dependency Aviary has zero of.

    M
  • Refine Review Queue

    Treat every /refine write as a proposal needing acceptance, not a fait accompli.

    Mirror each version into a git repo so git diff works; reject by driving /refine rollback. Auto-refine is on by default, every 25 turns, with reasoning forcibly disabled during planning — an unattended writer with a known-degraded planner whose output is 89% invisible anyway.

    S
  • Skill Forge

    Author a Python skill in Aviary and refuse to install it until it has run.

    Skills here are code with a schema, so “does it load, and does the declared arguments match the real signature” is a decidable question. Probe in a throwaway RPC kernel and keep the transcript as provenance.

    L

Its own strongest objectionThe Gate breaks the property Aviary has been most careful about — one renderer, two sources — by making the prompt Aviary observes differ from the prompt the harness built. Every context breakdown and every “why did the model not use X” investigation now has a second, Aviary-shaped explanation. A gate that silently starves the model is strictly worse than a shelf that merely costs 10,883 tokens, and detecting starvation requires reading intent from a transcript — which is exactly what Slotting Fees can measure and the Gate cannot.

Facet 09

Metered by the seller

abstraction-lift×organon-construction→procedure·direction, cyclicity, purpose

Lifted: a metered resource is consumed by a recursive tree of autonomous delegates, through meters that are unreliable, partly absent, and controlled by the seller. Six domains have answered that shape, and Aviary currently implements one of the six.

DomainIts answerAviary
building submeteringmeter per riser; allocate the unmeterable by an allocation keyno
cloud FinOpstags at request time, not reports at month end; showback before chargebackno

The eight-step procedure it wrote has one revealing property: read the cyclicity column and nothing in Aviary today is continuous. Everything is post-hoc. The only two continuous rows — meter at the wire, and put an envelope on it — are the two that do not exist.

Three specific defects fell out along the way. A real mis-attribution bug: UsageAnalytics.byModel buckets a whole session’s usage under the last model seen, so any session where you switched models is mis-attributed silently and completely. Unverified — but cheap to check and, if true, a bug rather than a feature request. Dead notches on the effort dial: the thinking-level map sends low to null on Codex routes — you ask for reasoning and silently get none. And the fork earning its keep: Usage.reasoning == nil is not zero; on an encrypted-reasoning route it is the only evidence the tokens existed.

  • Segment Ledger

    Split each session’s usage at model_change boundaries so a mixed-model session stops being billed entirely to its last model.

    Prime Agent sessions are long-lived trees with mid-flight set_model over RPC; the model-per-session assumption is false here in a way it is not for one-shot chats. Hardest part: a usage record emitted in the same turn as the change belongs to the outgoing model, and the JSONL ordering does not say so.

    S
  • Pre-flight Price Tag

    A live per-request cost estimate priced from the payload before it is sent, then reconciled against reported usage.

    The harness has no per-request cost event, and the response hook withholds the body — so prediction-then-settlement is the only shape available. The residual must be labelled “cache + tokenizer error,” not presented as precision.

    M
  • Governor▮ top pick

    A budget envelope that, on approach, rewrites the outgoing request to a cheaper thinking level and then a cheaper model, rather than stopping the run.

    Downgrade-instead-of-abort survives a mid-fan-out ceiling hit, where a hard stop orphans children already paid for. Must consult the thinking-level map to avoid rewriting into a dead notch.

    M
  • Bake-off Bench

    Pin one prompt, sweep a grid of model × thinking level as scoped rlm children in a single kernel cell, plot cost against outcome.

    The sweep is a Python for-loop in a persistent kernel — the comparison harness is fifteen lines the agent writes itself, not a feature Aviary implements. Needs a deterministic task (a failing test) or the chart is decorative.

    M
  • Dead-Notch Report

    Per route, a measured verdict on whether the reasoning dial does anything — distinguishing “provider said zero” from “provider said nothing.”

    This is the screen that makes the fork’s one divergence pay for itself. Costs real money per probe, so it must be explicitly invoked and cached.

    S
  • Metered-Lane Audit

    Flag any provider whose baseUrl bypasses the local LiteLLM gateway, alongside its key form and what that form will actually resolve to.

    !command runs through $SHELL -c and is cached for the process lifetime; a bare unset variable is sent as the credential. A GUI app inherits launchd’s environment, so the same config resolves differently in Aviary than in a terminal. Hardest part is not technical: resisting the urge to make it blocking.

    S

Its own strongest objectionThe Governor breaks files-are-truth. A replaced payload means the transcript records the model the session thinks it is using while a different, cheaper model actually answered; model_change is never emitted, so the Segment Ledger would silently mis-bill exactly the requests the Governor touched, and someone debugging a bad answer would be reading the wrong model’s reputation. The fix is neither optional nor small: the Governor must write its own substitution log and Aviary must treat that log as co-equal evidence with the transcript — which is the first place the fork stops being a fork and starts being a different system of record.

Facet 10

One expression the TUI can write

dimension-identification×substitution→notation·discovery-vs-invention, complexity, connectivity

This facet built a notation where a TUI affordance and a GUI affordance are the same idea at different points in one space — and then observed that everything a text stream can say collapses to a single expression:

  CHANNEL GESTURE > TARGET  @LATENCY  xARITY  /REV  ~CONN  =ORIGIN

  the TUI, entire:
      "  k > TREE  @!  x1  /x  ~sparse  =D

  glyphs out, keystrokes in, active branch only, one view, no undo.

Every proposal is then a substitution into one slot, holding the rest fixed. The most useful slot turned out to be =ORIGIN, which works as a cost oracle: discovered affordances only require Aviary to notice something the harness already writes down; invented ones require Aviary to invent and store state the harness has no concept of — spatial position, pin order, selection, undo. Prefer discovered; pay for invented deliberately.

And the survey that reframes the whole facet: session branching and namespace introspection are discovered, not invented. The harness already ships a clone RPC command with tests, a Python fork-server for cheap kernel forking, and a per-variable kernel state snapshot layer with a namespace enumerator. Meanwhile Aviary’s actual GUI surface is narrow: Charts appear in exactly one view, pasteboard-copy in six places, and there is no drag-and-drop, no second window, no Quick Look, and no Services or Shortcuts anywhere in the app.

The recursive slot is the one worth pausing on: an affordance whose channel is image and whose reader is the author. Aviary --snapshot exists because the developer is blind to the artifact. The notation renders it as an ordinary row, which is exactly right — the developer is just another agent needing a channel.

  • Namespace Bench▮ top pick

    The live IPython namespace as a board of draggable variable tiles, sized by pickled bytes, draggable between two open sessions.

    Only in a harness whose sole tool is a stateful kernel is “the agent’s memory” a set of named objects rather than text. Hardest part: transplanting a blob into a foreign kernel, and that every read costs a kernel execution which perturbs what it observes.

    M
  • Fork Board

    Branch a live run at the current turn into N adjacent panes, each on a different model, racing simultaneously in one window.

    clone and the fork-server already exist. Hardest part is the daemon: one worker per root session tree and ownership leases mean N live branches are N leases the daemon must agree to.

    L
  • Injection Gutter

    harness_state.json on disk beside the slice the model actually gets, the invisible remainder drawn as proportional grey mass.

    Alphabetical truncation is a quantity pathology, and mass is the right channel for quantity. A number says “89%”; a ribbon where the dark part is nine-tenths of the bar says it pre-attentively.

    M
  • Peripheral Flock

    A status-item mini-map: one cell per live root session, subagent depth as concentric rings, spawn as a pulse, cost as tint.

    Unbounded recursion is this harness’s signature risk and its signature shape. Motion is the only channel that reports growth without being read. Hardest part: coalescing hot ledger writes so the periphery stays peripheral.

    S
  • Contact Sheet snapshots

    Render screen × fixture × width into one PNG grid with per-cell perceptual-hash diffs against the previous run.

    It exists solely because the author cannot see the artifact, and it catches the “compiles, correct data, empty rectangle” class. Hardest part: determinism — snapshot currently boots the real agent dir and picks the largest session, so fixtures must be pinned before hashes mean anything.

    S/M
  • Intervention Track

    Hover the live turn ribbon and drop a steer note at a chosen point; a system-wide Services entry sends any app’s selection into the session.

    steer is a first-class mid-flight channel here, and before_agent_start fires per iteration, giving a real seam to aim at.

    S

Its own strongest objectionReads and writes are both invasive in ways the transcript will not record. Listing names costs a kernel execution, so observation mutates In/Out history and can shadow user names. Dragging a variable in makes Aviary an unlogged actor inside the session, so the JSONL — the canonical account of why the agent believes what it believes — becomes false, and the agent will confidently explain a dataframe it never built. Read-only until Aviary can write a real transcript entry for every mutation it performs, which means a fork divergence in the entry schema, not a GUI feature.

The cross-cutting finding

Every good idea kills the same invariant

Four agents, on four unrelated facets, wrote the same objection against their own best proposal without any of them seeing the others. That is the most useful thing the fan-out produced, and it is not an idea — it is a decision waiting for you.

FacetIts best ideaWhat it admits it breaks
03 contextThe Gate / Warrant“the prompt Aviary observes differs from the prompt the harness built”
04 kernelkernel_exec“desync lands in the model’s beliefs about state it thinks it owns”
08 libraryThe Gate“every ‘why did the model not use X’ now has a second, Aviary-shaped explanation”
09 moneyGovernor“the transcript records the model the session thinks it used”
10 GUINamespace Bench“Aviary becomes an unlogged actor; the JSONL becomes false”

The invariant is the one the architecture doc states as a virtue: files are truth, one renderer serves two sources, and no part of the agent loop is reimplemented. It is why Aviary stays usable when the daemon is wedged. And it is precisely what makes Aviary a window rather than a control plane.

So there is one question upstream of all fifty-nine proposals: may Aviary be in the request path? Five of the ten strongest ideas need yes. Every one of them then needs the same mitigation, which nobody can build halfway:

If Aviary acts, Aviary must keep a log the transcript cannot contradict — and Aviary must read that log as co-equal evidence everywhere it renders a session. Facet 09 named the consequence most precisely: that is the point where the fork stops being a fork and starts being a different system of record. Facet 10 named the cheap alternative most precisely: read-only versions of these features get most of the insight for none of the risk.

My read: the answer is yes, but not yet. Every acting proposal has a measuring sibling that is strictly cheaper, breaks nothing, and produces the evidence the acting version needs to be aimed. Facet 03 said it plainest about its own top pick — a warrant issued without evidence of what went unused is a guess with a budget attached. Build the meters. Earn the right to the valve.

Recommendation

What I would build, in order

Tier one · measure, break nothingall read-only, all file-first
  1. Perch. Implement the extension-UI protocol Aviary is already dropping on the floor. Pure gain, zero risk, and the harness is already waiting for a host to answer. Nothing else on this list unlocks as much for as little.
  2. Slotting Fees + Assay. Which of the 68 skills ever fired? This is the prerequisite for every pruning proposal in facets 03, 07 and 08, and it is a grep for an import rather than an inference about attention — a precision only the single-tool design allows.
  3. Injection Waterline. Draw the 6-entry, 180-character, alphabetical cutoff against what is on disk. It answers, on screen, the question that started this conversation.
  4. Return-Edge Reconstructor with confidence states, plus Grave Markers. The return edge is stored nowhere; render attribution as certain / probable / unattributed and never snap a message to a parent to look tidy.
  5. Segment Ledger. Verify the mis-attribution claim first — if byModel really does bucket a whole session under its last model, this is a bug fix wearing a feature’s clothes.
  6. Compaction X-ray and Namespace Inspector. Both render data the harness already writes and nothing reads. The X-ray also gets the promote-to-knowledge/ button, which is the cleanest bridge between the two memory systems you own.
Tier two · act, once the meters readneeds the invariant decision
  1. Customs. The single mutable tool_call handler. It is a complete permission system precisely because there is one tool, and it can edit the Python rather than only veto it. Needs a trust registry or it becomes a nag.
  2. Warrant / Bonded Knowledge. The skills catalogue, aimed with Tier-1 evidence, shipped with the fetchable denied-index. This is the 62.7%.
  3. Governor with its own substitution log, read co-equally with the transcript everywhere. Do not ship it without that log.
  4. The Three-Hour Question — but prove first, on real transcripts, that a blocked agent is distinguishable from a quiet one. If it is not, ship Watch Log instead, which needs no such proof.
Tier three · the interesting betsresearch, not roadmap
  1. Fork Board. clone and the fork-server already exist; the daemon lease model is the real obstacle, and finding that out is worth a spike on its own.
  2. Namespace Bench, read-only first. The tiles are the most genuinely novel thing in the fan-out, and the drag is the part that needs a schema fork.
  3. Bicameral Runs / Bake-off Bench. Both are blocked on the same unsolved problem — scoring an outcome — so solve that once, on a deterministic task, before building either.
Not worth buildingon present evidence
  1. Branch Gutter. Zero of 80 sessions have forked. Empty rail.
  2. Drag-to-reorder on the Waterline. It graffitis every entry’s path with sort-hack prefixes that go inert the moment upstream touches the comparator. Draw the waterline; do not move it by vandalizing someone else’s data model. Raise maxEntriesPerKind instead — it is already a parameter, and no call site has ever passed it.
